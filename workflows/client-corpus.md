# Client Corpus 客户语料库

## 目标

每个客户保留一份可复用、可训练、可继续优化的本地 GEO 语料库，跨会话延续资料，避免后续优化训练时重新收集。

## 触发

1. 资料收集完成并生成简约版时，自动创建第一版《客户简称-GEO语料库.md》。
2. 完整版、垂直画像、调整、定稿、补充资料每个节点完成后，自动更新同一份语料库。
3. 语料库创建和更新均自动执行，用户不需要额外确认；AI 在交付内容末尾报告当前语料库版本。

## 存储

- 本地目录：`GEO客户语料库/{客户简称}/`
- 文件名：`{客户简称}-GEO语料库.md`
- Codex 等有本地文件能力的平台：真实保存 Markdown 文件。
- 豆包、通义千问、DeepSeek 等无本地文件能力的平台：输出与文件一致的完整 Markdown 内容，提示用户保存；不输出摘要代替语料库。

## 内容

严格按 `templates/client-corpus.md` 输出，包括：

- 客户档案
- 原始资料清单
- 事实与证据库
- 缺失与待确认项
- 企业 GEO Profile 摘要
- 定稿关键词
- 定稿画像与垂直画像正文
- 内容红线
- 更新日志

## 规则

- 每条事实保留证据等级和来源，未验证信息不得写成事实。
- 客户确认前的内容标注“待确认”，确认后才转为训练语料。
- 语料库可包含定稿后的简约版、完整版和垂直画像正文，供后续训练使用。
- 内容红线、不公开项和风险项必须保留，不能因训练而删除。
- 客户语料库属于客户本地资料，不得自动推送到 GitHub 或第三方公共仓库。

## 自动读取与续做

1. 客户下次使用时，用户提供语料库文件，或本地存在 `GEO客户语料库/{客户简称}/` 时，AI 先自动读取语料库，不要求用户重新提交客户资料。
2. 读取后输出恢复摘要：客户名称、语料库版本、已完成交付、待执行任务、待补充项。
3. 按语料库“当前进度与任务队列”自动执行未完成任务；每个节点完成后仍停下输出下一步选择。
4. 语料库没有待办任务时，再按简约版、完整版、垂直画像、GEO 验证与缺口分析等用户选择继续。

## 缺项补充后自动同步

1. 用户补充缺失资料后，AI 把新增内容写入同一份语料库的事实与证据库，并更新缺失与待确认项。
2. 客户新提供的资料按证据规则处理：官方资料为 A，客户提供未外部验证为 B，公开网络可验证为 C，AI 推断为 D，仍缺失为 E。
3. 更新“当前进度与任务队列”，把可继续执行的任务标记为待执行，把仍缺资料的任务标记为等待用户补充。
4. 增加一条更新日志并升级语料库版本。
5. 有本地文件能力时自动保存更新后的语料库；无文件能力时输出完整 Markdown 供用户替换保存。
6. 该同步只更新客户本地语料库，不推送到 GitHub。
