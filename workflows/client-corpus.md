# Client Corpus 客户语料库

## 目标

每个客户保留一份可复用、可训练、可继续优化的本地 GEO 语料库，跨会话延续资料；恢复时只读最小文件，更新时只写变化，避免整份重载和整份重写。

记忆口诀：先读索引、再读最小文件、更新只写变化。

## 存储模式

### 目录模式（有本地文件能力的平台）

- 根目录：`GEO客户语料库/{客户简称}/`
- 分文件模板：`templates/client-corpus/`
- 文件：`00-当前进度.md`、`01-事实与证据.md`、`02-定稿关键词.md`、`03-画像正文.md`、`04-缺失清单.md`、`05-更新日志.md`
- 客户档案放在 `00-当前进度.md`；事实与证据、内容红线放在 `01-事实与证据.md`；缺失清单单独放在 `04-缺失清单.md`

### 单文件模式（无本地文件能力平台）

- 模板：`templates/client-corpus-single-file.md`
- 首次创建或用户明确要求完整导出时输出全文，供用户保存。
- 后续更新只输出“本次变更内容”和新的“当前进度与任务队列”，不重复整份输出；用户需要整份保存、导出或恢复原文件时，随时明确要求完整导出即可。

## 触发

1. 资料收集完成并生成简约版后，先询问“是否把本次成果加入客户语料库？”；用户确认后才创建第一版，未确认不创建。
2. 已建立语料库的客户，在完整版、垂直画像、调整、定稿、补充资料每个节点完成后，先询问“是否把本次成果更新进客户语料库？”；用户确认后才增量更新。
3. 创建和更新都以用户确认为前提；AI 在创建或更新后报告当前语料库版本。
4. 用户暂不创建时，不强迫保存；后续节点完成时仍可再次询问“是否需要补建客户语料库”，由用户决定。
5. 用户暂不更新时同样不写入；后续节点完成时仍可再次询问是否需要补更新。

## 读取与续做（确认后）

1. 客户下次使用时，用户提供语料库，或本地存在 `GEO客户语料库/{客户简称}/` 时，AI 不自动下载、不自动读取，先询问“是否使用该客户语料库？”，不要求用户重新提交客户资料。
2. 用户确认使用后，目录模式先只读 `00-当前进度.md`，输出恢复摘要：客户名称、语料库版本、已完成交付、待执行任务、待补充项。
3. 后续按用户选择或任务队列决定读取范围：
   - 补充资料、核验证据：读 `01-事实与证据.md` + `04-缺失清单.md`
   - 关键词调整：读 `02-定稿关键词.md`
   - 画像调整或训练复用：读 `03-画像正文.md`
   - 版本追溯：读 `05-更新日志.md`
4. 不一次读取全部客户文件，不重读已归档全文。
5. 用户确认使用并恢复当前进度后，按“任务队列”执行未完成任务；每个节点完成后仍停下输出下一步选择。
6. 用户暂不使用语料库时不下载、不读取，直接按本次提供的资料继续流程；后续仍可再次询问是否需要使用。

## 增量更新

1. 用户补充缺失资料后，AI 先询问“是否把本次补充资料更新进客户语料库？”；用户确认后，才把新增事实写入事实与证据文件，并更新缺失清单、任务队列、版本号和更新日志。
2. 客户新提供的资料按证据规则处理：官方资料为 A，客户提供未外部验证为 B，公开网络可验证为 C，AI 推断为 D，仍缺失为 E。
3. 目录模式只更新发生变化的文件：
   - 事实变化：更新 `01-事实与证据.md`
   - 缺项变化：更新 `04-缺失清单.md`，并把阻塞状态同步到 `00-当前进度.md`
   - 关键词/画像变化：更新 `02-定稿关键词.md` / `03-画像正文.md`
   - 每次变化：在 `05-更新日志.md` 追加一行，并升级 `00-当前进度.md` 版本号
4. 单文件模式只输出变化块，不整份重复；保存方式由用户维护原文件。
5. 该同步只更新客户本地语料库，不推送到 GitHub。

## 规则

- 每条事实保留证据等级和来源，未验证信息不得写成事实。
- 客户确认前的内容标注“待确认”，确认后才转为训练语料。
- 语料库可包含定稿后的简约版、完整版和垂直画像正文，供后续训练使用。
- 内容红线、不公开项和风险项必须保留，不能因训练或压缩删除。
- 客户语料库属于客户本地资料，不得自动推送到 GitHub 或第三方公共仓库。
