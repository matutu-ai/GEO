# Confirmed Decisions（2026-10-23 当前有效）

- 每轮一份 `GEO 关键词与画像.md`：初次仅词模式，不生成画像；用户一次选词并指定品牌/业务画像范围后，默认仅画像模式。完整模式仅用于选定后明确要求合并导出。
- `templates/delivery.md` 是唯一交付版式；程序、独立 Skill 和分发包使用同一文件。历史模板不进入默认入口。
- 四类词顺序固定：品牌词、搜索词、问答词、意图场景词；按用户最新“还是去掉吧”，取消意向程度列，仅保留推荐词、短词根两列。意向保留内部合同，不向用户展示；客户补词入口保留。搜索词以场景/人群＋产品业务为主，不强塞企业定位。
- 推荐表不是封闭名单。允许客户补词或描述需求；适配则保留，过泛或生硬则给1–2个优化候选，新业务或证据缺口集中确认。仅补词不等于选定；改写不覆盖原词且不自动批准。CLI复用requested_keywords接入、approved_keywords确认，语义适配由Skill核对。
- 客户主体与经营产品品牌分开。品牌词短词根使用客户确认的品牌名；其他词根逐条提取，通常3–10字，官方名称不强行截短。
- 搜索词不带地区，问答词默认不带地区；只有明确要求时意图场景词可使用确认地区。含地区客户原词保留记录并说明未纳入本轮推荐。
- 当前有效规则：首轮可覆盖多条已确认业务，按主营核心度和意向度分组/排序；词数随事实支撑的不同需求动态生成，不设固定上下限、不用同义词凑数。客户原词原样保留，和系统建议区分来源及确认状态。画像阶段仍由用户指定品牌或单一业务范围。
- 意向按实际任务/采购/调研语义判断，不能仅凭“需要”或意图场景词类型直接判高意向。系统建议不是平台实测热词。
- 画像默认完整版，简约版仅明确要求时使用。品牌画像与业务画像二选一，不默认两套，不每个词一套。都固定九项；搜索角色卡只作内部依据，不是第十项。
- 完整版每项800–1000字，不是九项合计；证据或字数不满足则停止交付，不编造、不降级冒充。章首记录已选词，词只限定重点，不作为事实证据。
- 用户明确选词才写approved_keywords；只说继续不是全选。CLI画像模式无有效已选词时停止；跨轮requested_keywords保留选定条目、类型、短词根与业务线。完整模式词表只列已选词。
- 一次收集资料，只对影响结论的缺失/冲突集中追问；导出前自动完成一次结构检查，不把检查拆成用户多轮确认。
- 仓库是 Skill 唯一编辑源。通过 `scripts/package_skill.py` 同步安装和分发包，内容变化更新版本；不再手工维护第二份同名 Skill。
- Standard 程序继续通过现有版本化 JSON 与 GEO-BD 协作，上游 Prescription 只读；无效输入停止，不静默回退 Legacy。
- Legacy V4 仅显式启用并保留兼容；不修改 GEO-BD，不扩展默认交付到文章、发布或平台效果验证。
- 独立 Skill 按客户事实生成并填统一模板，不要求客户准备内部处方 JSON；具备执行环境时运行随包检查脚本，没有执行环境时明确说明并按模板检查。
