# {客户简称} GEO 语料库（目录模式）

> 用途：Codex 等有本地文件能力的平台，把每个客户的语料库存成独立目录，恢复时先读 `00-当前进度.md`，执行任务时再按需读取，避免整份重载、整份重写。

## 目录文件

```text
GEO客户语料库/{客户简称}/
|-- 00-当前进度.md   # 每次恢复会话先读此文件
|-- 01-事实与证据.md # 补充资料、核验证据、训练前读取/更新
|-- 02-定稿关键词.md # 关键词调整、画像生成前读取/更新
|-- 03-画像正文.md   # 调整画像、训练复用、新画像前读取/更新
|-- 04-缺失清单.md   # 判断能否继续任务时读取/更新
`-- 05-更新日志.md   # 版本追溯、恢复摘要时读取/更新
```

## 读写规则

1. 创建：生成简约版后先询问“是否把本次成果加入客户语料库？”，用户确认后才按本目录模板一次创建全部文件；未确认不创建。
2. 读取：恢复客户上下文时先只读 `00-当前进度.md`；执行哪个任务，再读对应的一个或两个文件。
3. 更新：每个交付节点完成后先询问“是否把本次成果更新进客户语料库？”，用户确认后只写发生变化的文件或块；每条更新在 `05-更新日志.md` 追加一行并升级版本号，不重写无关文件。
4. 内容红线、不公开项和风险项必须保留，不能因训练或压缩删除。
5. 客户语料库只属于客户本地资料，不自动推送到 GitHub 或第三方公共仓库。
6. 用户暂不创建或更新时不写入；后续节点完成时仍可再次询问。

## 无本地文件平台

豆包、通义千问、DeepSeek 等无文件能力平台改用 `templates/client-corpus-single-file.md` 单文件模式：每轮只输出本次变更内容与当前进度摘要，完整导出仅在首次创建或用户明确要求时输出。
