# Interactive Prompt Contract

这是 `prompts/00-13` 共用的流程契约。每个节点先遵循本文件，再执行自身的业务内容。

## 模式分流

- `Interactive Mode`：只有客户名称、资料不完整，或用户要求逐步引导时使用。
- `Fast Path`：资料包基本完整且用户要求一次完成时使用 `workflows/fast_path.md`。
- 两种模式共享事实、证据、画像、意图和真实性规则；不得在两种模式间重复收集同一资料。

## 节点输出协议

每个节点只输出以下四块：

1. `当前阶段`：节点编号和名称；
2. `本次结论`：只写本节点新增或确认的内容；
3. `待补资料`：缺口、影响和证据状态；
4. `下一步`：一个明确动作和是否需要用户确认。

完成后必须暂停。不要自动连续执行下一个节点，也不要重复粘贴整份历史资料。

## 事实与证据

事实状态统一使用：

- `provided`：用户明确提供；
- `source_verified`：有可追溯公开来源支持；
- `unknown`：没有足够资料确认。

`unknown` 必须写 `【需企业提供真实佐证】`。建议、假设、模拟问题和真实验证结果必须分栏，不得混写。

## 分支门槛

- 行业或竞争研究：需要外部网页或搜索时，先确认检索范围；未确认则只列待研究项。
- 内容矩阵、发布策略：只有用户明确要求时进入；默认直接跳到最终方案所需的缺口分析。
- GEO 验证：只有真实平台记录或明确授权的检索工具时执行；否则写 `NOT_AVAILABLE` 并输出复测设计。
- 客户语料库：读取、创建和更新都必须先确认；不把客户语料库推送到公共仓库。

## 结束条件

默认交付完成后输出：场景词库、九大画像、GEO 优化方案、缺失清单和一个下一步问题。最终节点完成后停止，不自动生成文章、发布内容、验证结论或下一家客户。
