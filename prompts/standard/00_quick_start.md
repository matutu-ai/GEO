# GEO 关键词与画像快速启动

使用前读取同包的 `templates/delivery.md`；这是唯一交付版式。词表固定两列“推荐词｜短词根”，各类用途写在标题下面。先选词，再画像。

默认只给用户这一段，不先展示内部流程：

```text
请一次提供以下资料；未知项写“未知”，其他缺项我会合并追问一次：

1. 企业/品牌名称与主营业务
2. 产品或服务
3. 企业定位
4. 目标客户
5. 主要使用场景
6. 已有关键词或客户常用问法（可选；保留原句）
7. 业务优先级（如有多条业务，请标出主营核心业务；未知可留空）

我先按主营核心度与已确认需求，分业务推荐四类候选词；数量随有依据的需求动态确定，不设固定条数、不用近义词凑数。只展示推荐词和短词根，暂不输出画像。你选定词和画像范围后，再生成品牌画像或指定业务画像，固定九项，每项 800–1000 字；缺资料集中列出，不编造。
```

首轮词表末尾固定引导：

> 请选择已有词，或直接补充你想做的词／需求，并指定品牌画像或业务画像＋业务名称。

词表按业务核心度分组展示，组内优先呈现高意向且事实支撑充分的词；四类词仍分别使用固定两列。表后可以给一个可选训练组合，用户只需回复词本身或编号，并指定画像范围；组合不自动视为已选。

例如：`选择“大作美居”“新房装修护脊床垫”，生成品牌画像。` 或 `选择“新房装修护脊床垫”，生成床垫零售业务画像。` 示例只展示回复方式，不能替客户确认业务。

## 交互规则

- 保留一次“选词＋画像范围”的用户决策；不逐阶段、逐词或逐画像重复确认。程序校验不是用户确认。
- 首轮默认仅词模式；仅画像模式不输出关键词表，只在画像章首记录已选词；完整模式只在选定后明确要求合并导出时使用，不列未选词。
- 画像默认完整版，每项 800–1000 字；简约版只在明确要求时使用。已给定所选词与画像范围时直接生成，不再重复核验已提供资料。
- 只选了词就只问画像范围；只说“继续”不能视为全选。选择品牌画像或业务画像其一，不默认生成两套。
- 推荐表不是封闭名单。补词先保留原文，核对业务，补齐分类和词根，意向只作内部判断；需要改写时给1–2个优化候选并一句话说明原因。仅补词不当作选定；明确选定且无需修改时直接继续。新业务或证据缺口集中补问。
- 只有关键事实缺失或冲突会改变主体、业务、政策或对外表述时，才一次合并所有必要问题；其他缺项标记“待补”。
- 四类关键词固定为品牌词、搜索词、问答词、意图场景词；具体框架见 `references/keyword-rules.md`。
- 分类按用户意图：搜索词是“在场景里找服务”，问答词是“比较/判断/选择”，意图场景词是“明确提出任务和需求”。先训练品牌词、搜索词，再补问答词、意图场景词。
- 系统推荐词是基于确认资料生成的候选，不是平台实测词。默认不搜索或抓取外部平台；只有用户明确要求时才研究外部词源，并记录来源和日期。
- 九大画像固定为产品或服务描述、产品或服务特点、品牌故事、用户痛点、信任背书、客户案例、社会贡献、客户评价、创始人介绍；品牌画像和业务画像共用此结构；完整版每项必须 800–1000 字，不合规则停止导出。
- 短词根出现在固定两列词表中；搜索角色、业务线、来源和状态保留为内部记录，不另加列或章节。
- 搜索词不得带地区；问答词默认不带地区；只有用户明确允许时，意图场景词才加入已确认地区。
- 仅交付一份结果；不要附加审计文件、重复检查报告或冗长流程说明。

## 程序边界

Standard CLI 首轮默认仅词模式；选词后将原文写入 `geo_preferences.approved_keywords`，指定 `output_mode: 仅画像模式`。业务画像再指定 `vertical_business`；品牌画像留空。跨轮把所选条目及类型、短词根、业务线保存在 `requested_keywords`，防止重新生成时丢失原词。只列为候选不代表已选定；未知、已排除、含禁用地区或业务不符的已选词阻止画像导出。

Skill 独立使用时沿用对话中明确的选择，填同一模板，交付前运行一次随包 `scripts/check_delivery.py`；程序导出已自动执行同一检查。CLI 不调用模型写长文，第二阶段需提供已确认的九项正文 `complete_personas` 或满足长度的事实正文；资料不足停止完整版交付。完整模式决定“已选词＋画像”的范围，完整版决定画像长度。缺少运行环境时只说明未运行脚本，仍按模板检查一次。
