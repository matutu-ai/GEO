# 四类 GEO 关键词规则

只使用以下四类，不再拆成多套互相重叠的词类。企业已确认事实限定推荐边界；客户原词与系统建议词分开标记。分类看用户意图，不只看句式或是否带问号。

| 类型 | 生成框架 | 训练用途 |
| --- | --- | --- |
| 品牌词 | 品牌名称；品牌 + 业务或已确认定位 | 训练品牌识别及品牌、业务、主体之间的稳定关联 |
| 搜索词 | 场景或人群 + 产品/业务，按需加需求修饰，不带地区 | 匹配用户在具体场景中寻找哪类产品或服务 |
| 问答词 | 业务/需求 + 对比、判断、选择或适配问题 | 训练比较、筛选和决策回答 |
| 意图场景词 | 明确动作/任务 + 使用场景 + 产品/服务业务 | 匹配用户已经提出的任务或需求与对应方案 |

## 内部选词依据

- 先区分客户企业品牌与经营产品品牌。例如大作美居是客户主体，丝涟是其经营产品品牌；不能因业务名含丝涟，就把客户品牌替换为丝涟。授权关系只按已确认资料描述。
- 品牌词的短词根使用客户已确认的企业/品牌名；经营产品品牌、业务和定位放在推荐词中，不用产品名或服务名称替换客户品牌词根。
- 从已确认的主体、主营业务、定位、目标客户、使用场景、用户痛点提炼词根。每条推荐词单独提取对应的核心表达；内部保留原始事实 ID、来源和状态。
- 短词根通常 3–10 个字；品牌官方名称或已确认业务名不适合截短时保留原词。缺失类别标待补，不补造词根。
- 业务根、场景根、需求根不带地区；提取地区以客户明确提供的服务范围为准，不从模糊语句推断。
- 搜索词写成自然、紧凑的检索短语，如“新房装修护脊床垫”“家庭睡眠空间床垫配套”。不再强制“使用场景 + 业务 + 定位”三项齐全；仅有助于区分需求时加入已确认特点，不硬塞企业宣传定位。问答词围绕产品/业务提出一个决策问题；意图场景词写清具体任务、场景和所需产品/服务。品牌词可以是品牌名称，不强行扩成长句。
- “丝涟床垫零售”可作为内部业务名称；用户问法应为“丝涟床垫怎么选？”，不能机械生成“丝涟床垫零售怎么选？”或“用床垫零售解决需求”。搜索词不统一加“我需要”，问答词与意图场景词也不互换句式凑数。
- 最终推荐词仍需把短词根与已确认的业务、场景或品牌连接，扩展为用户可能输入的自然搜索或提问；“我需要”“怎么样”不能单独作为最终词。
- 客户原词保持原样；只有能直接从原词或确认资料得到短词根时才填写。词根、自然问法和客户事实都不代表实际搜索热度，也不保证 AI 推荐。

## 来源与意图边界

- 先以客户确认事实限定品牌、业务、定位、人群和场景；客户提供的搜索词/问法原样保留，不能为贴合模板而改写。
- 默认系统建议是依据确认资料生成的候选表达，不是搜索平台实测词。Standard 默认不执行外部搜索或抓词，也不宣称热度、排名或 AI 推荐概率。
- 只有用户明确要求外部词源研究时，才采集搜索联想、问答区或指定平台的真实表达；逐条保留原句、来源平台/页面和采集日期，并区分“平台观察词”与“系统建议词”。平台出现不代表适配客户，仍需经过事实匹配与客户确认。当前 Standard JSON 合同只记录客户提出/系统推荐，尚不承载平台来源字段；未升级合同前，平台观察结果不能伪装成现有 CLI 的可追溯字段。
- 搜索词回答“在这个场景里，我去哪里/找什么服务”；问答词回答“怎么比较、判断或选择”；意图场景词表达“我有这个具体任务/需求，需要这项业务”。同一表达只归入最贴近主要意图的一类，不重复凑类。
- 例：`跨境独立站 SEO优化服务商` 是场景下找服务的搜索词；`SEO优化服务商怎么选？` 是决策问答词；`我需要提升跨境独立站自然流量，想找 SEO优化服务` 是明确需求场景词。例句仅演示分类，不代表实测热度。

## 生成与筛选

- 先生成品牌词和搜索词作为首轮训练重点，再补问答词与意图场景词；合并客户明确提出的词并保留来源，不把词根直接当作最终推荐。
- 多业务客户先按已确认的主营核心度排序，再分别围绕有事实支撑的产品、客户和场景生成候选；结果按业务分组、组内按意向强度排序。某条业务缺少对应场景或人群证据时不强行造词，并集中标记待补。
- 搜索词以场景/人群＋产品业务为主，必要时加选购、配套、体验等需求；不凑固定字数，不把同一需求改写多遍。短词根提取核心产品/业务主题，不复制整条搜索词或只截场景名。
- 问答词采用贴近真实决策的自然问题句式，优先覆盖对比、判断、选择；未采集并记录来源时，不称为平台实测问法；不得虚构价格、效果或政策答案。
- 意图场景词用自然表达写清用户要完成的事情、所处场景及对应产品/服务；避免只把问答词加上“我需要”。
- 推荐词数量不设固定下限或上限，按业务核心程度、已确认需求方向和意向强度动态确定；只保留有明确差异且资料支持的词。客户原词全部保留并与系统建议区分，不因数量上限静默丢弃；重复表达可合并并说明。
- 交付只使用 [统一模板](../templates/delivery.md) 的两列：推荐词、短词根。用途放在每类标题下面；来源、角色、业务线和确认状态留在内部记录。关联不上时列入待补资料，不硬绑。
- 系统推荐搜索词不得含地区；问答词默认不带地区。地区从整句检查，包括企业定位和人群描述中的地名。仅用户明确要求且地区已确认时，意图场景词可加入地区。含地区的客户原词原样保留在内部记录，并在待补资料说明未纳入本轮推荐，不改原词冒充客户认可。
- 保留 `客户提出 / 系统推荐` 与 `已确认 / 待确认` 状态。推荐不等于客户批准。
- 表格后用一句话给出一个可选的训练搭配方向，优先围绕同一业务选择一个核心搜索词，再搭配相关品牌词、问答词或意图场景词。该组合只是便于选择的建议，用户确认前不写入已选词。

## 选词与画像衔接

首次只输出候选词，结尾请用户一次选词并选择品牌画像或业务画像及业务名称。不要推荐完就自动生成画像。用户可选择任意数量和类型的相关词，不要求四类全选。品牌画像可覆盖企业整体；业务画像只围绕用户指定的一条已确认业务。已选词与未选词分开，后续画像只使用本轮已选词作为方向，未选词不得自动补入。

品牌词绑定客户主体；搜索、问答、意图场景词绑定对应业务的需求，选择其中任一类都可作为该业务画像的内容重点。不强制“选品牌词只能做品牌画像”，也不将每个词变成一套画像。若所选词跨业务线且用户选择垂直业务画像，只围绕其指定业务生成；其他已选业务词不带入画像，必要时一次说明范围。

## 客户补词：推荐表不是封闭名单

用户可以直接输入原词，也可以描述想吸引的客户、想解决的需求。只补问影响业务匹配的缺口，不重启整套资料收集。

- **适配且清楚**：保留原文，归类、提取短词根，内部判断意向，加入同一候选表；不因未被推荐而拒绝。
- **过泛、过长或生硬**：内部保留原词，根据已知场景给1–2个优化候选。在本类表下用一句话说明“原词→建议词及原因”，不增加表格列或另建报告。未确认场景不能写成客户事实。
- **新业务或证据不足**：集中确认是否实际经营及服务边界，不能用工商范围或一句新词就认定主营业务。已确认但属于另一业务线的词另轮处理。
- **地区或无依据的承诺**：保留原始记录，提出去地区或客观表达的优化候选，不能默改为客户已确认词。
- **同义重复**：保留客户明确选择的写法，避免同一需求多条凑数；调整客户原句须说明并一次确认所选版本。

“补充一个词”只加入候选；“就用这个词做业务画像”是明确选择，适配后直接继续。若系统改写，则只确认改写候选，不再复核未变化的词。

CLI复用`requested_keywords`加入补词（建议对象格式，写明keyword、keyword_type、root_phrase、intent_level、business_line），来源保持CLIENT_REQUESTED、状态PENDING_CONFIRMATION。系统改写词作为新的建议记录，不冒充客户原词；用户确认后才能加入`approved_keywords`。程序只检查字段、地区和业务线一致性，语义与事实适配由Skill核对，不宣称CLI自动理解任意新业务。

## 意向程度与内部字段

每条推荐词必须同时记录：短词根、四类词类型、意向等级、搜索角色、业务线、场景、地区、来源、确认状态、关联九大画像板块。意向等级只作内部判断，不在交付词表展示；高/中/低意向不替代四类词分类，不代表实测热度、排名、转化概率或词的总体价值。

- 高意向：采购、供货、集采、报价、招标、预约体验或明确购买/交付需求。不能仅凭“我需要”“项目”或归为意图场景词就判高意向。
- 中意向：怎么选、是否适合、对比、推荐、方案调研。
- 低意向：品牌名、品类名和基础认知；只作品牌关联与内容铺垫。

建议整体训练组合为高意向 60%、中意向 30%、低意向 10%，不要求每篇文章机械凑比例。客户搜索词与 BD 背调词必须分开，企业工商查询、合作核验和案例背调词不得混入客户获客词包。
