# geo-keyword-profile-template

基于《GEO核心词&画像套用模版参考建议》整理的 Codex Skill，用于生成 GEO 核心词、画像段落、发布数量策略和讯灵GEO发布规则。

## GEO V3 架构

企业资料 → 资料清洗 → 证据识别 → GEO Profile → 行业研究 → 竞争研究 → 搜索意图 → 关键词矩阵 → 九大画像 → 垂直画像 → 内容矩阵 → 动态发布 → GEO验证 → 缺口分析 → 内容补强 → 再次验证。

新增模块：

- `schemas/`：统一数据结构
- `workflows/`：模块化执行流程
- `templates/`：输出模板
- `tests/`：测试集
- `docs/`：架构文档

## 快速学习

其他 AI 学习时只先读 `LEARN.md` 和 `SKILL.md`，掌握核心规则后按需读取 `references/`，减少学习时间。

投喂学习后必须先分析仓库框架，再提示用户提供客户资料，并询问是否需要《客户资料填写表》，以便按同一结构精准收集资料；用户直接给资料时仍按原流程继续。

## 适用智能体

豆包、通义千问、DeepSeek 等所有通过本仓库学习本技能的 AI 智能体，必须严格按本框架输出，不得自行更改结构。

## Skill 更新机制

- 源仓库：https://github.com/matutu-ai/GEO
- 每次新对话加载本技能时，先检查源仓库最新版本
- 之前学习过本技能的对话再次对话时，自动确认仓库版本，变化后先更新再继续
- 自动检查地址：`https://raw.githubusercontent.com/matutu-ai/GEO/main/SKILL.md` 及 `references/` 下对应文件

## 同步权限（仅仓库所有者）

GitHub 同步只能由仓库所有者本人执行：

- 普通用户、客户和代理商对话中，AI 不提供、不执行“同步仓库”选项。
- 豆包、通义千问、DeepSeek 等无 Git 执行环境的平台一律不执行、不承诺同步。
- 只有仓库所有者本人在本地 Codex/Git 环境明确说“上传到库”“同步到库里”“更新到库里”时，AI 才执行同步，并在完成后告知仓库地址与提交信息。

## 本地客户语料库

- 每次为客户生成简约版时自动创建《客户简称-GEO语料库.md》，完整版、垂直画像、调整、定稿后自动更新同一份语料库。
- 有本地文件能力的平台保存到 `GEO客户语料库/{客户简称}/`；无文件能力平台输出完整 Markdown 供用户保存。
- 内容模板：`templates/client-corpus.md`；流程：`workflows/client-corpus.md`。
- 客户后续做优化、训练或新对话时，直接投喂这份语料库即可继续。
- 下次使用语料库时自动读取并恢复客户上下文，按“当前进度与任务队列”自动续做未完成任务。
- 用户补充缺失资料后，自动回写同一份语料库并升级版本，不等用户再次说明背景。

## 学习完成提示

学习本技能后，AI 应输出仓库框架分析摘要，再提示用户提交客户资料，并询问是否需要《客户资料填写表》。示例：“我已学习完 GEO V3 企业增长闭环版，已完成仓库框架分析。请提交客户资料；需要的话，我可以先输出《客户资料填写表》帮你逐项收集。”可接收企业介绍、产品资料、案例、图片、docx、xlsx、纯文本、网页链接等。

## 每步操作后的下一步提示

每个操作节点完成后，AI 必须停下并输出下一步选择，等待用户确认后再继续，不自动进入下一步。

## 标准交互流程

1. 学习完成 → 分析并摘要仓库框架 → 提示提交初始资料，询问是否需要《客户资料填写表》
2. 提交资料，或确认不需要表格 → 自动生成简约版，并自动创建本地《客户简称-GEO语料库.md》
3. 简约版完成 → 选择：完整版词和画像 / 垂直业务画像 / 其他业务推荐方向 / 调整 / 定稿 / 补充资料

## 功能

- 核心词：品牌词、业务词（搜索词/问答词）、场景意图词
- 业务词框架：业务使用场景 + 业务本身 + 业务属性定位；不确定时可用 AI 全行业挖掘
- 业务词展示分类：核心同义、功能属性、场景长尾、B端工程、疑问转化、简写口语、地域组合、否定词包
- 业务词展示结构：搜索词按业务方向分组，问答词单独输出
- 业务词=搜索词推广；问答词=核心词训练问句，单独输出
- 简约版业务词：拓展后输出优先推荐建议，结合产品/服务 + 公司定位
- 业务词优先推荐：按 B 端、C 端人群分别给出建议
- 业务词流程：优先推荐 → 提示词扩展 → 优先训练词 + 说明
- 完整版业务词：按“我需要一个某业务我会搜哪些词”生成
- 关键词规则：问答词/搜索词不要带地区
- 关键词规则：业务词和问答词一律不能带地区
- 画像：10 个画像字段
- 所有版本画像严格按 九大板块框架输出
- 所有画像（企业画像、垂直画像、简约版、完整版、客户交付文件）一律按 九大板块框架生成
- 所有需要生成画像的场景（单一业务画像、企业画像、垂直画像等）一律按 九大板块框架生成
- 所有画像严格按九大板块内容标准给出结果
- 完整版企业画像与垂直业务画像一致，按 九大板块框架生成
- 画像填写框架：产品或服务描述/特点的框架逻辑与行业案例参考
- 画像内容标准：按《画像标准-2026.8.xlsx》填写内容，框架仍按 九大板块
- GEO V3：企业 Profile、证据系统、行业研究、竞争研究、搜索意图、关键词矩阵、内容矩阵、GEO验证、Gap分析
- 两版流程：先输出简约版，确认后再生成完整版
- 简约版完成后的决策点：扩写完整版 / 生成业务垂直画像 / 只调整核心词 / 直接定稿简约版
- 完整版：每个画像段落基本控制在 800-1000 字
- 业务垂直画像：支持单个业务，也支持批量多个业务分别生成专属画像
- 垂直画像与完整版画像框架一致，统一按 九大板块输出
- 发布数量策略与讯灵GEO发布规则
- 学习完成后的下一步选择提示
- 投喂学习后的框架分析摘要
- 客户资料填写表提示与 Markdown 模板
- 本地客户语料库自动生成与更新
- GitHub 同步权限边界：仅仓库所有者

- 制定发布数量计划
